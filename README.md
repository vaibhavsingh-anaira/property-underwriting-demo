# SMB Risk Verification (NYC restaurants)

Checks the answers on a small-business insurance application against **real** public records and the business's own
website, and shows the evidence behind every fact. Nothing is synthetic: every number comes from a downloaded record,
a fetched web page or a logged LLM call.

Demo scope is Manhattan food businesses (10,606 inspected establishments). Scope, limits and the LLM are set in
`config.yaml`; the same pipeline runs for all five boroughs by changing `scope.boroughs` and `scope.osm_bbox`.

## What it answers

| Application question | Sources that answer it |
|---|---|
| Serves alcohol? | NYS liquor licence · business website (Gemini) · OpenStreetMap bar/pub tag |
| Open after midnight? | Business website · OpenStreetMap opening hours · 311 late-night noise complaints (single-tenant lots only) |
| Deep frying? | Business website menu |
| Delivery? | Business website · OpenStreetMap |
| Outdoor seating? | NYC Dining Out licence · business website · OpenStreetMap |
| Business history | First health inspection · liquor licence first issue · legal entity formation date (NY register) · health grade, closures, critical violations · FDNY summonses |
| Building | Year built, floors, class (PLUTO) · open DOB and active ECB violations (whole building, labelled as such) |

Each fact is resolved by source trust (official record > the business's own website > absence of an official record >
crowd and complaint signals). When sources disagree the fact is flagged as a **conflict**: those are the questions an
underwriter should ask.

## Sources (all real, all public)

| Name | Dataset | Join key |
|---|---|---|
| inspections | [NYC DOHMH restaurant inspections](https://data.cityofnewyork.us/d/43nn-pn8j) | anchor (inspection ID, BIN, BBL) |
| liquor_licences | [NYS Liquor Authority active licences](https://data.ny.gov/d/9s3h-dpkz) | name + address, or name + location |
| complaints_311 | [NYC 311 service requests](https://data.cityofnewyork.us/d/erm2-nwe9) | BBL |
| pluto | [NYC PLUTO tax lots](https://data.cityofnewyork.us/d/64uk-42ks) | BBL |
| dob_violations | [NYC DOB violations](https://data.cityofnewyork.us/d/3h2n-5cm9) | BIN |
| ecb_violations | [NYC DOB ECB violations](https://data.cityofnewyork.us/d/6bgk-3dad) | BIN |
| dob_permits | [DOB NOW approved permits](https://data.cityofnewyork.us/d/rbx6-tga4) | BIN |
| fdny_inspections | [FDNY mandatory inspections](https://data.cityofnewyork.us/d/kfgh-h6re) | BBL |
| fire_summonses | [OATH hearings, FDNY summonses](https://data.cityofnewyork.us/d/jz4z-kudi) | BBL + respondent name |
| dining_out | [NYC Dining Out licences](https://data.cityofnewyork.us/d/fpeh-f7ci) | BBL + name, or location + name |
| corps (on demand) | [NYS Department of State active corporations](https://data.ny.gov/d/n9v6-gdp6) | legal name from licences |
| osm | OpenStreetMap via Overpass (ODbL, attribution required) | name + location |
| websites | each business's own site (URL from OpenStreetMap), robots.txt respected | business |
| Google Maps reviews | Gemini grounding with Google Maps, **live in the app only** | name + location |

Google Maps content is never stored, never turned into a fact and never used in matching or scoring: Google's Maps
Platform terms prohibit saving reviews and creating content from them. The app shows it live, with Google Maps source
links, for the underwriter to read.

## Pipeline

```
ingest  -> data/raw/*.parquet            11 public datasets + OpenStreetMap, paginated, idempotent
link    -> businesses, links             entity resolution; every link keeps method, score and distance
corps   -> corps, corp_queries           NY company register lookups for licence legal names (cached)
crawl   -> web_pages                     business websites; headless Chromium fallback; incremental
extract -> llm_calls, web_facts          Gemini, strict JSON schema; quotes must appear verbatim in the page
ledger  -> observations, facts           evidence ledger + resolution + conflicts
evaluate-> reports/evaluation.md         accuracy against official records, coverage, conflicts
serve   -> demo app                      search, business profile, application check, live review insight
```

Storage is a single DuckDB file (`data/smbv.duckdb`) plus raw Parquet. Every stage reads the previous stage's tables,
so stages can be re-run independently; `crawl`, `extract` and `corps` only process new work.

## Measured results (Manhattan, 12 Oct 2026)

Full numbers are regenerated by `smbv evaluate` into `reports/evaluation.md`. Headline figures from the current run:

| Measure | Result |
|---|---|
| Businesses (inspected food establishments) | 10,606 |
| Linked to a liquor licence / OpenStreetMap / fire summonses / Dining Out licence | 43% / 45% / 30% / 12% |
| Building data (year built, floors, class) | 98% |
| Legal names found in the NY company register | 66% |
| Websites with usable text (400 fetched) | 64% (20% needed headless rendering, 11% blocked by robots.txt) |
| Gemini yes/no answers whose quote is verbatim in the page | 87% (the rest are discarded) |
| `serves_alcohol` from website vs. liquor licence | 89% precision, 99% recall where the site states it |
| `serves_alcohol` from OpenStreetMap bar/pub tag vs. licence | 90% precision, 22% recall |
| Businesses with at least one conflict between sources | 146 |

A hand review of the 13 website-vs-licence disagreements found 11 businesses that clearly serve alcohol (Morton's,
Nakamura's beer and sake list, Revel & Rye's cocktails): their licence is missing or was not matched. Two were extraction
errors (a tiramisu's coffee liqueur; a customer review quoted on IHOP's page). Hand-checked samples of 20 links per
matching method were 19-20/20 correct for name+address, name+location and Dining Out links.

Defects found in the source data and handled: PLUTO publishes lot IDs as decimals; the liquor licence file records some
Manhattan premises under the wrong county; licence addresses use ranges ("175 179 W 4TH ST") and alternate frontages
(Le Bernardin: 155 W 51 St vs 787 7th Ave); ZIP codes differ between datasets for the same address.

A pipeline defect was also found and fixed: offset paging ordered by the portal's internal row id is not stable (pages
overlap and skip rows: one download had 67k duplicate summons rows). Each source now downloads as one snapshot and the row
count is checked against the server's count; the run fails if they differ.

## Run

```bash
uv venv .venv --python 3.12 && uv pip install --python .venv/bin/python -e ".[dev]"
.venv/bin/python -m playwright install chromium        # headless fallback for JavaScript sites
.venv/bin/smbv all                                      # ingest -> evaluate (about 15 minutes for Manhattan)
.venv/bin/smbv serve --port 8800                        # http://localhost:8800
.venv/bin/python -m pytest -q tests
```

Gemini uses the same credentials as `tampering-check` and `preinspection-car-ml` (Vertex AI service account from AWS
Secrets Manager). To use another mechanism set `gemini.credentials.source` to `file`, `adc` or `api_key` in
`config.local.yaml`. Set `SOCRATA_APP_TOKEN` to raise open-data rate limits (optional).

## Scaling

- **Geography:** add boroughs in `config.yaml`; all source filters are generated from the scope.
- **Volume:** `crawl.max_sites` and `extract.max_businesses` cap the demo run; set them to `null` for every business.
  Crawl and extraction are incremental and concurrent (`workers`).
- **Freshness:** re-run `ingest` on a schedule; the open-data portals update daily.
- **Storage:** DuckDB handles tens of millions of rows locally; the same SQL moves to a warehouse unchanged.
- **New sources:** add an entry to `SOURCES` in `src/smbv/ingest.py` and an observation block in `src/smbv/ledger.py`.

## Known limits

- DOB NOW approved permits and FDNY mandatory inspections are downloaded but not yet used in any fact; OpenStreetMap
  drink:* tags are not used yet.
- Building-level records (DOB/ECB violations, 311) describe the whole building. For lots with several food businesses
  they are labelled building-level and not attributed to one tenant.
- A missing liquor licence is weak evidence of "no alcohol": licence matching misses some businesses. It is ranked below
  the business's own website and surfaces as a conflict rather than a verdict.
- Facts from websites cover only businesses whose site could be fetched and read (see `reports/evaluation.md`).
- Public data shows facts and history, not insurance losses. Predicting losses needs a carrier's claims data.
- NYC Open Data is provided "for informational purposes" without warranty; review the portals' terms before commercial use.
